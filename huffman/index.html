1. Build the tree

Each distinct byte starts as a tree of one leaf, weighted by how often it occurs. Repeatedly take the two lightest trees and join them under a new node whose weight is their sum, until one tree is left. The first one taken goes on the 0 side and the second on the 1 side; on equal weights the older tree goes first. Rare bytes end up deep, with long codes, and common bytes end up near the top.

5. Self-checks

What this does not show

  • It codes bytes (UTF-8), not letters: a character such as "é" is two bytes and two symbols here. That keeps the comparison with 8-bit codes exact.
  • The size of the table a real decoder needs is not counted in the encoded size. It is why short texts rarely gain from Huffman coding in practice.
  • Huffman coding gives each byte a whole number of bits. It is the best such code (the page checks that on small alphabets in its test file, not in your text), but it can sit up to one bit per byte above the entropy; arithmetic coding can come closer.
  • The entropy H is measured from your own text's byte counts. It says nothing about how English, or any other source, would behave.
